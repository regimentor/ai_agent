# ai_agent — контекст репозитория

## Что разрабатывается

CLI AI-агент на Rust: локальный бинарник, который оркестрирует LLM + tools
(цикл observe → decide → act → update state).

Стадия: **ранний каркас** — workspace поднят, логики агента ещё нет.

## Стек

- Rust, Cargo workspace, `resolver = "2"`
- Edition **2024** у членов workspace
- Язык общения с пользователем: **русский**

## Текущая структура

```
ai_agent/
├── AGENTS.md           # always-on: в каждом чате грузить project-info
├── Cargo.toml          # workspace root
├── Cargo.lock
├── crates/
│   └── cli/            # единственный member, bin `cli`
│       ├── AGENT.md    # описание крейта (обязательно)
│       ├── Cargo.toml
│       └── src/main.rs # пока Hello, world!
└── .agents/skills/     # project skills (этот файл)
```

- Package name бинарника: `cli` → запуск: `cargo run -p cli`
- Зависимостей у `cli` пока нет
- `target/` — артефакты сборки, не коммитить

## Описание крейтов: `AGENT.md`

У каждого крейта в его корне лежит **`AGENT.md`** — описание назначения, границ ответственности и ключевых решений этого крейта.

- Путь: `crates/<name>/AGENT.md`
- Workspace-уровень контекста — этот skill (`project-info`); детали конкретного крейта — только в его `AGENT.md`
- Перед работой над крейтом читать его `AGENT.md`; при смене роли/границ — обновлять файл
- Новый крейт без `AGENT.md` не считается завершённым

## Архитектура (целевая)

Пока один крейт. При росте — разделять ответственность, не сваливать всё в `cli`:

| Крейт | Роль |
|-------|------|
| `crates/cli` | UX: CLI args, REPL/IO, точка входа |
| `crates/core` (когда появится) | agent loop, state, политика остановки |
| `crates/tools` (когда появится) | реализации tools, схемы, side effects |
| другие `crates/*` | по мере нужды (providers, memory, …) |

Инварианты агента (когда появится код):

- явный stop condition + бюджет (steps / tokens / wall time)
- ошибки tools — first-class, не «молча повторить»
- секреты и destructive actions — не отдавать в произвольный tool-call без контроля

## Правила кода

- Новые пакеты **только** в `crates/`, затем добавить в `members` корневого `Cargo.toml`
- У каждого крейта есть `crates/<name>/AGENT.md` с описанием этого крейта
- Общие зависимости — через `[workspace.dependencies]`, в членах: `{ workspace = true }`
- Не создавать корневые пакеты вне workspace
- Не коммитить секреты (`.env`, API keys) и не класть их в код
- Не коммитить без явной просьбы пользователя
- Предпочитать маленькие, сфокусированные диффы; не плодить README/docs без запроса

### Добавить новый крейт

```bash
cargo new crates/<name> --lib   # или --bin
# затем: members в корневом Cargo.toml
# создать crates/<name>/AGENT.md (назначение, границы, зависимости)
# при необходимости: path-зависимость из cli/core
cargo check -p <name>
```

### Типичные команды

```bash
cargo build
cargo test
cargo check -p cli
cargo run -p cli
```

## Перед изменениями

1. Убедиться, что этот скилл загружен (корневой `AGENTS.md` требует это в каждом чате)
2. Сверить `members` в корневом `Cargo.toml` с фактическими крейтами
3. Прочитать `AGENT.md` затрагиваемых крейтов
4. Не ломать layout workspace без обсуждения с пользователем
5. Если цель продукта / стек LLM / список tools ещё не зафиксированы — уточнить, а не выдумывать
